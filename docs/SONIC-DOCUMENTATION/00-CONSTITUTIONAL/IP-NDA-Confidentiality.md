# IP NDA Confidentiality

> Status: Framework defined, no entries logged yet — **legal review required before relying on this document**

## Purpose

Records Sonic's intellectual-property ownership posture and confidentiality practices, and defines the gate for anything that risks exposing proprietary material (source code, AI pipeline design, tenant data, business plans) outside the team. This document is a working framework, not a substitute for actual legal counsel — anywhere below marked **TEMPLATE / PLACEHOLDER** must be reviewed by a lawyer before being relied on for a real NDA, contractor agreement, or IP dispute.

## Scope

- Source code and architecture of Sonic (`backend/`, `frontend/`, `AI-Conversation-Intelligence-Architecture/`) and all documents under `docs/` and `SONIC-DOCUMENTATION/`.
- Tenant data processed by the platform (call audio, transcripts, derived analytics) — governed jointly with `docs/08-security-architecture.md` and `05-AI-GOVERNANCE/` for AI-specific handling.
- Business material: pricing, roadmap, prospective-customer information, this constitutional document set itself.

## IP Ownership Posture (working statement — TEMPLATE / PLACEHOLDER)

All code, designs, and documentation produced for Sonic are intended to be owned by the Sonic venture (founder/company entity), not by individual contributors in their personal capacity, consistent with standard work-for-hire practice for a founder-led SaaS product. **This is a stated intent, not a substitute for actual IP-assignment agreements** — before onboarding any contractor, employee, or co-founder, get a real IP assignment / invention agreement drafted by counsel; do not rely on this paragraph as legal protection.

## Confidentiality Practices

- Repository access is restricted to active contributors; this is enforced at the hosting-platform level (repo visibility/permissions), not within this document.
- Tenant data must not be used outside the production/authorized-development context (e.g., copying real tenant audio into a public bug report or demo without consent is a confidentiality breach).
- Any third party (contractor, advisor, prospective investor, integration partner) who needs to see source code, architecture docs, or tenant data before a formal agreement is in place should sign an NDA first — see the gate below.

## NDA Gate

**Trigger:** any disclosure of Sonic source code, non-public architecture/security documentation, or tenant data to a party outside the current team.

**Process:**
1. Confirm the recipient needs access to material covered by scope above (not just a general product demo, which typically doesn't need an NDA).
2. Use a standard mutual or one-way NDA (template TBD — **PLACEHOLDER**, obtain from counsel or a reputable template source rather than drafting from scratch).
3. Founder signs/approves on behalf of Sonic.
4. Log the disclosure below.

## Owner

**Founder** owns IP and confidentiality decisions and is the sole signer of NDAs at this stage. There is no in-house legal counsel; material decisions here (real IP assignment agreements, contractor agreements, actual NDA templates) should be escalated to outside counsel rather than resolved solely within this document.
